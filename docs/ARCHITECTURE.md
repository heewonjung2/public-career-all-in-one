## 1. 통합 취업 전략 최적화 (`services/strategy.py`)

### 1-1. 자격증 조합: 비선형 0/1 배낭 문제
- 결정변수 x_j ∈ {0,1}: 미보유 가산대상 자격증 j를 취득할지 여부
- 목적함수: `max Σ_c p_c · (Bonus_c(S ∪ {x}) − Bonus_c(S)) / Cap_c`
  - `p_c`: 기업 선호 가중치 `(1/우선순위)^k`. k는 전략 계수(1순위 집중형은 3)
  - `Bonus_c`: 해당 기업 **검증된 규칙**으로 계산한 가점(동일 종별 최고 1개, 영역별 인정 개수, 최대 3개, 12점, 총 20점, 유효기간·기준일)
  - `Cap_c`: 기업 일반 자격증 가점 상한(정규화 기준). 기업별 체계가 다르므로 원점수를 합산하지 않음
  - 적격/부적격 전형은 점수가 아니라 지원 요건 충족 여부로만 다룸
- 제약조건:
  - `Σ 준비시간 ≤ 주간시간 × 기간 × 자격증 배분비율`
  - `Σ 응시료 ≤ 월예산 × 개월`
  - 보유 자격증 제외
  - 근거 검증 실패 항목 제외
  - "해석 필요" 영역은 기본적으로 제외(사용자 선택 시 포함)
- 해법:
  - 단독 개선량이 0보다 큰 후보(14개 이하)의 부분집합을 **완전탐색**해 정확한 최적해를 구합니다.
  - 가치가 비가산적이므로(같은 영역 1개 제한 등) 단순 정렬이나 선형 배낭으로는 최적을 보장할 수 없습니다.
- 비교: 단독 가치 순 탐욕법. 테스트에서 탐욕법은 같은 "안전" 영역 자격증 2개를 담아 0점 개선을 내고, 완전탐색은 다른 영역을 조합해 더 높은 가치를 냈습니다.

### 1-2. 주간 학습 시간 배분
- `max Σ_i w_i · ln(1 + h_i)  s.t.  Σ h_i = H(0.5시간 단위), h_i ≥ 0`
- `w_i = (공식 문항 비중 × Σ적용기업 선호) × 취약도^α × 공통과목 보정`
  - 취약도: 미시작·취약 1.0 > 보완 필요 0.8 > 준비 중 0.6 > 복습 필요 0.45 > 준비 완료 0.15
  - 공통과목 보정: 모든 목표 기업에서 공식 확인된 과목에만 적용
- 해법: 한계효용 탐욕법. 분리 가능한 오목 함수의 정수 자원 배분에서 이 방법은 최적입니다. 0.5시간 단위 전수 탐색과 같은 값을 냄을 테스트로 확인했습니다.
- 비교: 가중치 비례 배분보다 목적함수가 높습니다(예: 7.84 vs 7.68).

### 1-3. 전략 계수
| 전략 | 자격증 시간 비율 | 선호 지수 | 취약도 지수 | 기타 |
|---|---|---|---|---|
| 균형형 | 0.2 | 1 | 1 | 공통과목 ×1.5 |
| 1순위 집중 | 0.2 | 3 | 1 | |
| 가점 확보 | 0.4 | 1 | 1 | |
| 필기 집중 | 0 | 1 | 1.3 | |
| 최소 비용 | 0.1 | 1 | 1 | 예산 0 |

전략 평가 지표는 합격 확률이 아닙니다.

## 2. RAG (`services/rag.py`)
1. **색인**: 공식 출처가 검증된 공고의 PDF만 색인합니다(본문 9쪽 + 참고자료 61쪽 → Chunk 수는 `/api/documents/index` 응답 참고).
2. **Chunking**:
   - 페이지 경계를 유지합니다.
   - 제목(□, ○, [참고n], 1., 가.)에서 우선 분할하며, 약 700자 단위로 자릅니다.
   - 앞 Chunk의 2줄을 overlap으로 둡니다.
   - 표는 PDF 텍스트 줄 단위로 보존되며, 가점표 한 페이지가 대체로 1~2개 Chunk에 담겨 자격증명과 등급 행이 분리되지 않습니다.
3. **메타데이터**: recruitment_id, company_id, document_title·type, 연도, 유형, 직렬, 지역, 공식 URL, 첨부 URL, page_number, published_at, version_id, document_hash, verification_status
4. **토큰화**: 한국어 문자 2-gram 토큰을 쓰고, 조사·질문 어미를 제거하며, 도메인 동의어(졸업→학력, 나이→연령 등)를 확장합니다.
5. **검색**: SQLite FTS5 `bm25()`를 쓰고, **선택된 공고 버전(recruitment_id)으로 필터링**합니다.
   - 복수 기업 질문은 기업별로 분리 검색합니다.
   - 데이터가 없는 기업은 보류합니다.
6. **충분성 판단**: IDF 가중 질의어 적중률이 0.6 미만이면 "확인할 수 없습니다"로 답변을 보류합니다. 코퍼스에 없는 핵심어(예: 대행사, TOEIC, 합격선)가 빠지면 적중률이 크게 떨어지는 원리입니다.
7. **답변**:
   - 가점·중복·인정 질문은 규칙 엔진의 결정적 계산 결과와 엔진 근거 인용으로 답합니다.
   - API 키가 있으면 검색 Chunk만 전달해 LLM이 JSON으로 답하게 합니다. 인용문이 해당 Chunk에 실제로 있는지 정규화 비교로 검증하고, 하나라도 실패하면 보류합니다.
   - 키가 없으면 AI 답변 없이 검색 원문만 반환합니다(`retrieval_only`).
8. **개인정보**: 상담에는 자격증, 출생연도, 병역 등 계산에 필요한 필드만 쓰고, 대화는 서버에 저장하지 않습니다.
9. **벡터 검색**: 임베딩 API가 없어 미구현입니다. `search()`를 교체할 수 있는 구조입니다.

## 3. 정정 공고 변경 감지 (`services/versions.py`)
1. **파일 비교**: raw SHA-256이 같으면 "동일 파일"입니다.
2. **내용 비교**: 정규화 텍스트(공백 정리, 빈 줄 제거, 숫자·날짜·줄 구조 유지)의 SHA-256이 같으면 "메타데이터만 변경"입니다.
3. **원문 Diff**: `difflib.SequenceMatcher` 줄 단위로 added, deleted, modified를 구합니다.
4. **규칙 Diff**: 모집 인원, 직렬, 일정(접수 시작·마감, 필기, 면접, 발표), 지원 자격(rule_text, params), 인정 자격증 추가·삭제, 등급(가점) 변경, 등급별 점수, 상한·개수, 시험 과목을 비교합니다.
5. **중요도**(서비스 내부 알림 분류 기준):
   - 매우 중요: 마감일, 필기일, 지원 자격, 직렬, 인정 자격증, 가점
   - 중요: 인원, 과목, 절차, 발표, 면접
   - 일반: 그 외
6. **동일 모집 건 판정**:
   - 정정 대상 공고 번호가 명시되어 있거나 같은 기관·같은 공고 번호면 "same"
   - 기관, 연도, 반기, 유형이 다르면 "different"
   - 그 외는 "uncertain"이며 자동 연결하지 않습니다.
7. **영향 분석**: 이전 규칙과 새 규칙으로 `check_eligibility`, `calculate_bonus`를 다시 실행해 지원 자격·가점·보유 자격증 상태 변화를 구하고, 일정과 과목이 바뀌면 캘린더·로드맵 갱신을 안내합니다. 새 근거 중 원문 검증에 실패한 것이 있으면 자동으로 확정하지 않습니다.
8. **버전 관리**: `recruitment_versions`(version_number, 해시 2종, previous_version_id, fetched_at과 published_at 구분, verification_status)는 덮어쓰지 않고 추가만 합니다.
9. **알림**: `notifications.dedupe_key`에 UNIQUE를 걸어 같은 변경은 한 번만 알립니다.
10. **수집**: 수동 새로고침으로 JOB-ALIO 첨부를 다시 내려받습니다. 1분 내 재요청은 거절하고, 결과는 `collection_logs`에 기록합니다. 정기 스케줄러는 상시 실행 환경이 없어 비활성입니다.
