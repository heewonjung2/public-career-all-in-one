# 프로젝트 기획서: 공기업 All-in-One

## 1. 한 줄 소개
**청년 취업 정보 격차 해소를 위한 공식 데이터 기반 AI 취업 지원 플랫폼.** 공식 채용공고만을 근거로 개인의 지원 자격과 가점을 분석하고, 맞춤형 취업 준비 로드맵을 제공합니다.

## 2. 개발 배경
취업 정보는 넘쳐나지만, 취업준비생이 자신에게 필요한 정확한 정보를 찾아 구체적인 준비 전략으로 연결하려면 여전히 많은 시간과 노력이 듭니다.

개발자는 공기업 전산직을 준비하며 같은 불편을 겪었습니다. 기업마다 다른 지원 자격, 가점 기준, 필기 과목을 반복해서 확인해야 했습니다. 생성형 AI를 써도 부정확한 채용정보가 나오면 실제 지원 기회를 놓칠 수 있어, 정보의 신뢰성이 가장 중요하다고 판단했습니다.

## 3. 해결하려는 문제

### 3-1. 사회적 문제
1. **청년 취업 정보 접근성 격차**: 공고문을 해석하는 시간과 역량에 따라 준비의 질이 달라집니다.
2. **공공기관 채용정보의 파편화**: 기관별 사이트와 첨부파일(PDF·HWP·zip)이 흩어져 있습니다. 예를 들어 코레일의 자격증 가점표는 별첨 참고자료 PDF의 22~24쪽에 있습니다.
3. **생성형 AI 환각으로 인한 의사결정 오류**: 근거 없는 AI 답변은 지원 여부와 자격증 준비 같은 중요한 결정을 왜곡할 수 있습니다.
4. **불필요한 스펙 경쟁과 시간·비용 부담**: 가점에 반영되지 않는 자격증이나 출제범위 밖 과목에 자원을 씁니다.

### 3-2. 개인 차원의 불편 (Before)
공식 사이트 확인 → 첨부파일 다운로드 → 지원 자격 확인 → 가점 수동 계산 → 시험 과목 검색 → 일정 등록 → 교재 검색 → 학습 계획 수립. 이 과정에 주 약 3시간이 듭니다(개발자 본인 추정).

## 4. 핵심 가치
| 가치 | 정의 | 구현 |
|---|---|---|
| 정확성 | 공식 공고 원문에 있는 규칙만 사용 | 규칙 엔진(Python)으로 계산, AI는 점수를 만들지 않음, 미검증 규칙은 계산 차단 |
| 신뢰성 | 모든 결과의 근거를 확인할 수 있음 | 페이지·인용문 표시, 인용문의 원문 존재를 코드로 검증, "확인 필요" 상태 사용 |
| 접근성 | 누구나 같은 품질의 해석 결과를 이용 | 한 화면 통합, 원문 하이라이트 뷰어, 무료 공식 자료 링크, ICS 내보내기 |
| 개인 맞춤화 | 내 상황에 맞는 판단과 계획 | 스펙 기반 자격·가점, 출제범위 대비 공백 분석, 8주 로드맵 |

## 5. 핵심 차별점: 공식 출처 검증과 분석 근거 제공
- **허용 도메인 기반 출처 검증**: JOB-ALIO, ALIO, 기업 공식 도메인만 인정합니다. 기업명이 들어간 위장 도메인, 블로그·카페, 내부망 주소를 차단하고 리다이렉트를 단계마다 검증합니다.
- **근거 원문 자동 대조**: 규칙 파일의 인용문 77건을 서버 시작 시 공식 PDF와 대조합니다. 불일치하면 해당 규칙의 판단을 보류합니다.
- **3단계 상태 구분**: "인정/충족", "해석 필요", "공고에 기준 없음·가산대상 목록에 없음"을 구분해 0점과 확인 불가를 섞지 않습니다.
- **AI 역할 제한**: AI는 문서 구조화(선택)만 맡습니다. 결과는 Pydantic 스키마 검증과 인용문 재검증을 거친 뒤에도 "검증 필요" 상태로만 저장되며, 자동으로 계산에 반영되지 않습니다.

## 6. 주요 사용자
공기업 취업준비생, 졸업예정자, 여러 공기업에 동시에 지원하는 준비생, 자신의 스펙을 객관적으로 점검하고 싶은 사용자.

## 7. 기능 요구사항 (원 요구사항 유지)
P0, P1, P2 구분은 최초 요청서의 우선순위를 그대로 따릅니다. 현재 구현 상태는 README의 "구현 범위" 표를 참고하세요.

- **P0**: 대시보드, 스펙 입력·저장, 목표 기업 선택, 공식 공고 등록·분석, 출처·근거 표시, 지원 자격 판단, 검증된 규칙 기반 가점 계산, NCS·전공 안내, 부족 사항 분석, 맞춤 로드맵, 일정 안내, 실제 공식 공고 1건 이상 검증 → **모두 구현**(가점은 서류가 아닌 필기 가점, 아래 8-2 참고)
- **P1**: 자동 수집, HWP, 3개 기관, 교재 추천, 정기 탐색, 이메일, ICS·캘린더, 배포 → 교재 추천(링크)과 ICS 구현, 나머지는 구현 예정
- **P2**: 합격선 분석, 안정권 판단, 시뮬레이션, 최저가, 추천, 예측 → 시뮬레이션 구현, 합격선은 공식 데이터가 없어 "판단 불가"로 표시

## 8. 실제 공고 검증 결과
### 8-1. 대상
한국철도공사 2026년 상반기 신입사원 채용 공고 [2026-02호]입니다.
- 출처: JOB-ALIO `recruitview.do?idx=297210`, 2026-02-25 게시
- 직렬: 사무영업(IT), 공개경쟁, 수도권 10명
- 상태: 접수 마감된 과거 공고이므로, 차기 공고에 같은 기준이 적용된다고 단정하지 않습니다.

### 8-2. 공고에서 확인한 사실 (근거 페이지는 앱에서 열람 가능)
- **지원자격**: 연령은 제한이 없습니다. 다만 2009.1.1. 이후 출생자와 1965.12.31. 이전 출생자는 지원할 수 없습니다. 학력과 전공은 제한이 없고, 병역은 군필자 또는 면제자에 한합니다(공고문 p.2).
- **어학 요건과 IT 필수 자격증**: 공고에서 확인되지 않습니다. 따라서 앱은 "공고에 기준 없음"으로 표시합니다.
- **서류전형**: 자기소개서를 적격/부적격으로만 판정합니다. 따라서 "예상 서류 점수"는 산출 대상이 아닙니다.
- **가점**: 필기시험에 적용됩니다.
  - 일반 자격증은 공통직무 1개, 안전 1개, 직렬별 2개 중 최대 3개까지 인정하며 최대 12점입니다.
  - 등급별 점수는 기술사 5.5, 기사 4.0, 산업기사 2.5, 기능사 1.0입니다.
  - 동일 종별은 가장 높은 1개만 인정합니다.
  - 철도 직무 자격증은 최대 8점이며, 일반 자격증과 합쳐 최대 20점입니다.
  - 각 과목 40% 이상 득점자에게만 가점을 적용합니다(공고문 p.3, 참고자료 p.24~26).
- **필기시험**: 70분, 70문항입니다. 구성은 NCS 30문항(의사소통·수리·문제해결), 전공 30문항(컴퓨터일반: 정보보호개론, 운영체제, 데이터통신, 데이터베이스, 소프트웨어공학, 전자계산기), 철도법령 10문항입니다. 과목별 40% 미만은 과락이며, 필기 2배수를 선발합니다.
- **출제 대행사, NCS 유형(모듈형/PSAT형), 합격선**: 공식 공고에서 확인되지 않습니다.

### 8-3. 데모 프로필 분석 결과
| 보유 자격 | 결과 | 사유 |
|---|---|---|
| 한국사능력검정 1급 | 인정 2.5점 | 공통직무, 산업기사 등급 |
| 컴퓨터활용능력 2급 | 미반영 | 공통직무는 1개만 인정하므로 한국사 2.5점이 더 높음 |
| 정보처리기사 | 해석 필요 4.0점 | 목록 표기가 "사무영업 및 열차승무"이고, IT 적용 명시 문구 없음 |
| SQLD | 가산대상 목록에 없음 | [참고4] 목록에 없음 |
| TOEIC 860 / TOEIC Speaking IH | 공고에 기준 없음 | 어학 가점 규정 없음 |

**합계**: 확정 2.5점, 해석 포함 6.5점.

이 결과로 얻은 인사이트는 두 가지입니다. 첫째, 컴활 1급을 추가로 따도 공통직무 1개 제한 때문에 가점이 늘지 않습니다(시뮬레이터로 확인). 둘째, 준비 중인 인공지능·알고리즘·자료구조는 코레일 IT 출제범위 밖입니다. 이는 사회적 문제 4, 즉 불필요한 스펙 경쟁을 줄이는 데 연결됩니다.

## 9. 시스템 아키텍처
[ARCHITECTURE.md](ARCHITECTURE.md)를 참고하세요. 구조는 React SPA → FastAPI(REST) → SQLite + 공식 PDF 보관본이며, 선택적으로 Claude API를 사용합니다.

## 10. 기술 스택
React 19, Vite, TypeScript, Tailwind CSS v4, Lucide, FastAPI, Pydantic v2, SQLite, PyMuPDF, HTTPX, (선택) Anthropic SDK, pytest

## 11. 데이터베이스 설계 (구현)
- `profile`: 사용자 스펙(JSON)
- `documents`: 등록 문서(URL, 최종 URL, SHA-256, 페이지 텍스트, 검증 상태, 확인 시각)
- `roadmaps`, `study_tasks`: 로드맵과 체크리스트
- `notification_settings`: 알림 설정
- 채용 규칙은 `data/recruitment_rules/*.json`에 **공고 단위**로 저장합니다. 기업 단위가 아니므로 연도·직렬별 기준이 달라져도 대응할 수 있습니다.

## 15. 한계와 향후 계획
- 현재 분석 가능한 기관과 직렬은 1곳·1직렬입니다. 다음은 한국전력공사와 서울교통공사 공식 공고를 등록할 계획입니다.
- 공고 자동 수집(JOB-ALIO), HWP/HWPX 파싱, OCR, 이메일 알림, Google Calendar 연동이 남아 있습니다.
- 공식 합격선과 경쟁률 데이터를 확보한 뒤 안정권 분석을 추가합니다.
